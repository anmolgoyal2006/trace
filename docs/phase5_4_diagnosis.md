# Phase 5.4 — Ranking Ambiguity Diagnosis

## Purpose

Phase 5.3 aggregation produced a result where Track 66 outranked Track 29
(the known source track) under every aggregation statistic. This document
records the quantitative evidence, provides a structured framework for
visual inspection, and lists the hypotheses that could explain the gap.

No pipeline changes are made in this phase. The goal is diagnosis only.

## Hypotheses

The following explanations are mutually non-exclusive. Visual inspection
is required to assess which are supported by the evidence.

### H1 — Track 66 is the same physical person, different tracker ID

ByteTrack can assign a new track ID to the same person if there is a
tracking gap (e.g. the person left the frame briefly and re-entered).

Supporting evidence would be: identical or near-identical clothing,
similar build, similar pose, and a plausible timeline (Track 66 appears
~7 seconds after Track 29 ends).

Contradicting evidence would be: clearly different clothing, different
build, or simultaneous presence in frame.

### H2 — Track 66 is a genuinely different person with similar appearance

Two different people wearing similar clothing or sharing a similar build
can produce high OSNet similarity. OSNet was pretrained on Market-1501
and generalises well but is not infallible.

Supporting evidence would be: subtle differences in clothing details,
different build, different skin tone, or overlapping timestamps with
Track 29.

### H3 — Track 66 crops are higher quality than Track 29 crops

Track 29's gallery crops (the four that are not the query source) are
notably small: 101×276, 115×368, 124×363 px. OSNet resizes everything
to 256×128, but starting from a small crop means less original detail is
preserved. Track 66's crops are more uniformly mid-sized (140–155 px wide).

Supporting evidence: the mean gap (0.107) is much larger than the
max gap (0.015), which means Track 66's advantage grows when averaging
over all crops. This is consistent with Track 29 having some
low-information crops dragging its mean down.

### H4 — The query source crop is not representative of Track 29

The query was generated from Track 29's best crop (frame 0270, 222×634 px,
conf=0.895). The remaining Track 29 crops are smaller and lower quality.
If the other Track 29 crops are not good views of the same appearance,
their embeddings will diverge from the query embedding, pulling down the
track mean.

### H5 — Viewpoint or pose difference within Track 29

If several Track 29 crops show the person from a less canonical viewpoint
(partial back view, severe occlusion, or unusual pose), OSNet may assign
them lower similarity to the query front/side view.

## Implications for Phase 5.5 (Not Yet Decided)

The correct response to this diagnostic result depends entirely on the
visual judgment above. Possible outcomes:

| Visual judgment | Implication |
|-----------------|-------------|
| H1 confirmed (same person, ID split) | Tracker tuning or post-processing merging could fix this; it is a true positive that needs surfacing |
| H2 confirmed (different person, similar look) | The system is operating correctly but is limited by appearance ambiguity; a harder task than assumed |
| H3/H4 confirmed (quality gap) | Better query selection or gallery quality filtering could help; or using only top-quality crops per track for matching |
| H5 confirmed (pose gap) | Multi-view or temporal averaging strategies could help |
| UNCERTAIN | More diagnostic data needed before any change is made |

**Do not implement any Phase 5.5 change until the visual judgment is recorded above.**
